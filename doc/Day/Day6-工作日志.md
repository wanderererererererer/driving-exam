**文档/设计：**

- 明确**登录校验顺序**：**密码(1101) → 角色(1106) → 禁用(1102)**。
  理由：未通过密码校验的人**不应知道账号是否被禁用**（账号枚举防护的常见做法）。
- 确立**对照测试方法**：同一账号同一密码，**只改 role**，观察结果从 1106 变为 200 —— 这才是"角色校验生效"的有效证据。

## 四、关键技术决策

| 决策点 | 方案 |
|---|---|
| 错误码粒度 | "账号不存在 / 密码错误"合并为 1101（防账号枚举）；**角色不匹配单开 1106** |
| 校验顺序 | 密码 → 角色 → 禁用（保护账号状态不被未通过密码的人探测） |
| 404 语义 | 路径不存在 → **HTTP 404 + `ApiResponse`(1002)**，不再被 500 兜底捕获 |
| 测试方法 | 用**对照实验**（只改一个变量）证明某条校验真的生效 |

## 五、遇到的问题及解决方案

**问题 1**

- 现象：用「学员账号 + ADMIN 角色」登录返回 `1101 用户名或密码错误`，**无法判断究竟是角色不对、密码错、还是账号不存在**——测试存在盲区，答辩时也无法直观演示"我拦住了越权登录"。
- 原因：登录时把三种失败原因**统一压成同一个 1101**（出于账号枚举防护），代价是失去了可观测性。
- 解决：**新增 `ROLE_MISMATCH(1106)`**，角色不匹配单独返回。此后可用对照测试证明：
  - `student01 + 123456 + ADMIN` → **1106**
  - `student01 + 123456 + COACH` → **1106**
  - `student01 + 123456 + STUDENT` → **200 + token**
  → 同一账号同一密码，**只有角色不同**，结果从 1106 变 200，角色校验 100% 生效。

**问题 2**

- 现象：访问尚未实现的接口路径（如 `/api/student/study/knowledge-points`），返回 `code=500 系统异常`，并在日志里打印 **ERROR 级完整堆栈**。
- 原因：Spring Boot 3.2 在静态资源未命中时抛 `NoResourceFoundException`，被全局异常处理器的**兜底 `Exception` 分支**捕获（因为它是 `Exception` 的子类）。
- 解决：新增 `@ExceptionHandler(NoResourceFoundException.class)` 专属分支，返回 **HTTP 404 + `ApiResponse`(1002)**，日志降为 **WARN 且不打堆栈**。
  - 附带收获：这条同时验证了统一返回的一条设计决策——**业务失败走 HTTP 200，仅 401/403 用真实状态码**。对比可见：`1106` 走的是 HTTP 200，而 404 是 HTTP 404。
