## 3. 可从源码确认的系统功能

后端当前有 14 个 Controller、86 个映射，覆盖：

- 认证：登录、当前用户、资料、密码；
- 学员：刷题、错题、学情分析、模拟考试、预约、AI 问答、聊天；
- 教练：学员、学习数据、错题、AI 建议/确认、预约、聊天；
- 管理员：Dashboard、AI 统计、用户、绑定、知识点、题库/Excel、试卷、预约查看；
- RAG：知识入库、Qdrant 检索、检索上下文、DeepSeek 回答。

前端当前有 3 套角色布局和完整路由，包含工作台、学习、考试、预约、聊天、AI、管理 CRUD 和个人中心。

## 4. 可作为报告证据的设计决策

- JWT 只保存身份和角色，Day32 在拦截器中按 userId 复查 `sys_user` 状态与实时角色；
- 考试结算使用 `ExamFinalizer` 的 `ONGOING → 终态` 条件抢占，定时任务与手动交卷共用同一入口；
- 预约创建使用事务 + 教练行锁；状态流转使用预约行锁；
- AI 检索失败返回 4005，不把基础设施故障伪装成正常回答；入库失败返回 4006；
- Excel 导入全量预校验后事务写入，失败行有行号/字段/原因；
- 16 张表与实体基本一一对应，应用层维护关系，无数据库外键；
- 前端工作台使用真实接口，失败不显示为 0。
