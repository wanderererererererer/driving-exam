## 一、你（顾问）列出的"计划书 vs 实际"逐条确认

1. **DeepSeek 模型与参数 —— 以代码为准**
   - `application.yml` 的 `deepseek` 段：
     ```yaml
     deepseek:
       api-key: ${DEEPSEEK_API_KEY:}
       base-url: https://api.deepseek.com
       model: deepseek-chat        # 请求用官方别名
       temperature: 1.0
       top-p: 1.0
       connect-timeout: 5000
       read-timeout: 60000
     ```
   - `DeepSeekProperties`（`@ConfigurationProperties(prefix="deepseek")`）字段：`apiKey / baseUrl(@NotBlank) / model(@NotBlank) / temperature=1.0 / topP=1.0 / connectTimeout=5000 / readTimeout=60000`；请求体里 `topP` 用 `@JsonProperty("top_p")` 映射，`stream=false`。
   - **实测：请求发的是 `deepseek-chat`，服务端返回的实际模型是 `deepseek-flash`**；落库存的是**返回值**，不是配置别名。
   - 结论：计划书写的 `deepseek-v4-flash` **不对**；正确表述是「请求别名 `deepseek-chat` → 实际返回 `deepseek-flash`」。

2. **RAG 没有做，不要假设存在检索层**
   - `server/ai/` 下只有 3 个类：`AiChatService`、`AiChatServiceImpl`、`SystemPromptBuilder`。
   - 全仓库搜 `qdrant / bge / embedding / 向量 / vector / retriev` **无任何实现类、也无相关依赖**；只有 `AiChatRecord.referencesJson` 与 `SystemPromptBuilder` 的**注释**里提到"为 RAG 升级预留"。
   - 结论：AI 问答 = **纯 Prompt + DeepSeek**。报告/答辩**不要写 RAG**（如要提，只能写进"未来工作"）。

3. **学情分析前端 = 横向柱状图 + 折线图 + 短板表**（**不是雷达图**）
   - 理由：知识点只有 4 个、维度不够；且知识点是父子树、雷达要求维度相互独立。以实际前端为准。

4. 其余确认：**表数 = 15** ✓；题库管理**推迟到 Day19** ✓；**Day16~17 模拟考试已完成**（联调 21 请求 / 83 断言 / 断言失败 0）✓；后续顺序调整为 **预约 → 教练端 → 管理端** ✓。

CREATE TABLE `appointment` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键',
  `student_id` bigint NOT NULL COMMENT '学员ID',
  `coach_id` bigint NOT NULL COMMENT '教练ID',
  `subject_code` varchar(20) NOT NULL COMMENT '科目：SUBJECT_2/SUBJECT_3',
  `appointment_date` date NOT NULL COMMENT '预约日期',
  `time_slot` varchar(50) NOT NULL COMMENT '时间段',
  `status` varchar(20) NOT NULL DEFAULT 'PENDING' COMMENT '状态：PENDING/CONFIRMED/CANCELLED/COMPLETED',
  `remark` varchar(255) DEFAULT NULL COMMENT '学员备注',
  `coach_remark` varchar(255) DEFAULT NULL COMMENT '教练备注',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  `deleted` tinyint NOT NULL DEFAULT '0' COMMENT '逻辑删除',
  PRIMARY KEY (`id`),
  KEY `idx_student_id` (`student_id`),
  KEY `idx_coach_id` (`coach_id`),
  KEY `idx_subject_date` (`subject_code`,`appointment_date`),
  KEY `idx_status` (`status`)
) ENGINE=InnoDB;

CREATE TABLE `coach_student` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键',
  `coach_id` bigint NOT NULL COMMENT '教练ID',
  `student_id` bigint NOT NULL COMMENT '学员ID',
  `bind_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '绑定时间',
  `status` tinyint NOT NULL DEFAULT '1' COMMENT '状态：1有效 0解除',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_coach_student` (`coach_id`,`student_id`),
  KEY `idx_student_id` (`student_id`)
) ENGINE=InnoDB;

CREATE TABLE `student_subject_status` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `student_id` bigint NOT NULL COMMENT '学员ID',
  `subject_code` varchar(20) NOT NULL COMMENT 'SUBJECT_1~4',
  `status` varchar(30) NOT NULL DEFAULT 'NOT_STARTED'
      COMMENT 'NOT_STARTED/LEARNING/READY_FOR_EXAM/EXAM_PASSED/EXAM_FAILED',
  `mock_pass_count` int NOT NULL DEFAULT '0' COMMENT '模拟考连续及格次数',
  `last_mock_score` int DEFAULT NULL,
  `study_progress` decimal(5,2) DEFAULT '0.00',
  `exam_ready_suggest` varchar(30) DEFAULT NULL COMMENT 'READY/NEED_MORE/NEED_HELP',
  `ai_suggest` text,
  `ai_suggest_time` datetime DEFAULT NULL,
  `coach_confirm_status` varchar(30) DEFAULT NULL COMMENT 'CONFIRMED_READY/NOT_READY/NEED_HELP',
  `coach_remark` varchar(500) DEFAULT NULL,
  `exam_result` varchar(20) DEFAULT NULL COMMENT 'PASS/FAIL',
  `exam_date` date DEFAULT NULL,
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_student_subject` (`student_id`,`subject_code`),
  KEY `idx_status` (`status`)
) ENGINE=InnoDB;
